# GPT Balance Orchestrator

작업별 요구사항과 품질 기준에 적합한 모델 역량·추론 수준을 배정하고, 불필요하게 과도한 모델 사용을 피하여 토큰 효율을 높입니다.

중요도가 있는 코드 변경 기능, 리팩터링, 테스트 추가에만 사용하세요. 기능 단위는 파일이나 메서드가 아니라 테스트 가능한 하나의 응집된 동작입니다. 읽기 전용 작업, 문서 전용 작업, 사소하고 격리된 편집, 또는 사용자가 다른 절차를 요청한 작업에는 이 과정을 강제하지 마세요.

## 실행과 위임

주 세션은 범위, 소유권, 순서, route 변경, 위험 수용을 관리합니다. 병렬 실행이나 맥락 분리에 구체적인 실익이 있을 때만 실행을 위임하며, 그 외 하나의 연속된 작업은 직접 수행합니다. 어느 경우든 독립 검토는 필수입니다.

- 작업을 가장 작은 응집 단위로 나눕니다. 쓰기 path와 동작 계약이 겹치지 않는 단위만 병렬로 실행하며, 그 밖에는 순서대로 실행합니다.
- 각 하위 에이전트에는 목표, 완료 기준, 소유·인접/금지 path, 의존성, 검증 명령, route, 완료 보고 채널이 있는 제한된 브리프를 제공합니다. 사용자가 별도 작업을 명시적으로 요청하지 않는 한 사용자 소유 작업 대신 하위 에이전트를 사용합니다.
- 에이전트는 배정된 범위 안의 구체적인 문제를 다른 담당 에이전트와 직접 해결할 수 있습니다. 미해결 차단 요인과 범위·소유권·공유 계약의 변경 제안은 부모에게 보고하며, 부모가 변경을 결정한 뒤 해당 작업을 진행합니다.
- 부모는 모든 하위 보고를 관찰하고 평가한 뒤에만 완료합니다. 기본은 자동 최종 전달이며, 예상 보고 누락, 차단, 상위 의존성, 고위험 신호가 있을 때만 회수합니다. 같은 동작 맥락이 필요한 구현·테스트는 함께 유지합니다.
- 하위 보고에는 결과, 변경 path, 실행한 검사, 위험 또는 차단 요인이 포함되어야 합니다. 주 세션은 그 결정을 통합하며, 범위가 분명한 검토 수정은 현재 소유자에게 돌려보내고 더 넓거나 미해결인 작업은 다시 route합니다.

## 구현, 검토, 마무리

의미 있고 테스트 가능한 동작마다 소유자가 가장 작은 Red → Green → Refactor를 수행합니다. Red가 의미 없으면 이유를 설명하고 가장 가까운 실행형 검사를 수행합니다.

응집된 기능 또는 통합 결과마다 완료 기준, 회귀, 경계 사례, 테스트 품질을 보는 독립 검토를 한 번 받습니다. 보안, 권한 부여, 결제, 데이터 삭제, 마이그레이션, 배포에는 최종 검토자가 필요합니다. 작업 소유자가 집중 검사와 가장 작은 관련 통합·린트·타입·빌드 게이트를 실행합니다. 필수 검사가 통과하면 종료하고, 새 변경·실패·미해결 우려가 있을 때만 검사를 확대하거나 반복합니다.

## Routing

새 세션과 하위 에이전트에는 `gpt-6-luna`, `gpt-6.1-terra`, `gpt-6.1-sol`, `gpt-6-astra`만 사용합니다. 아래 Astra 예외 조건을 지키면서 복잡성·불확실성·위험도를 고려해 작업 적합성과 요구 품질을 기준으로 모델·추론 수준을 선택합니다. 조건에 맞는 모델을 사용할 수 없으면 차단 사유를 보고합니다.

| 판단 | Route |
| --- | --- |
| 1차 분류·기계적인 편집 | `gpt-6-luna` 낮음 |
| 완료 기준과 구현 방법이 명확한 구현·테스트 수정 | `gpt-6-luna` 중간 |
| 국소적인 코드·테스트 원인 분석·모호한 시각적 UI 진단 | `gpt-6.1-terra` 높음 |
| 기준이 명확한 브라우저 검증·시각적 UI 확인 | `gpt-6.1-terra` 중간 |
| 제공된 근거를 바탕으로 한 단순한 기능 문서 재작성 | `gpt-6.1-terra` 낮음 |
| 일반 기능 구현·테스트·계획·일상적인 조율 | `gpt-6.1-sol` 중간 |
| 아키텍처·어려운 진단·복잡한 시스템 간 작업 | `gpt-6.1-sol` 높음 |
| 고위험 최종 검토를 포함한 독립 코드·테스트 검토 | `gpt-6.1-sol` 높음 |
| 예외적으로 해결되지 않은 추론 문제 | `gpt-6-astra` 높음 |

위 표를 작업별 기본값으로 사용하되 실제 요구사항이나 결과에 근거가 있을 때 조정합니다. 매우 높음은 사용자가 명시적으로 요청하거나 유사 작업에서 품질 향상이 확인된 경우에만 사용합니다.

사용자가 명시적으로 요청한 경우를 제외하면, Sol 높음의 집중 진단과 독립적인 Sol 검토 후에도 진행을 막는 구체적이고 중요한 추론 문제가 남을 때만 Astra를 사용합니다. 복잡성이나 위험도만으로는 이 조건을 충족하지 않으며, 정보·도구 부족도 상향 사유가 아닙니다. Astra에는 관련 근거와 미해결 질문만 전달하고, 이후 실행은 Sol로 돌려보냅니다. Astra 매우 높음은 사용자가 명시적으로 요청한 경우에만 사용합니다.
