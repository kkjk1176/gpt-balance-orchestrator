# GPT Balance Orchestrator

[Read in English](README.md)

`GPT Balance Orchestrator`는 중요도가 있는 코드 변경 기능·리팩터링·테스트 추가를 위한 Codex 스킬입니다. 작업별 요구사항과 품질 기준에 적합한 모델 역량·추론 수준을 배정하고, 불필요하게 과도한 모델 사용을 피하여 토큰 효율을 높입니다.

병렬 실행이나 맥락 분리에 구체적인 실익이 있을 때만 실행을 위임하며, 그 외 하나의 연속된 작업은 주 세션이 직접 수행합니다. 어느 경우든 독립 검토는 필수입니다.

## 유지하는 정책

- 병렬 작업의 쓰기 path와 동작 계약은 겹치지 않습니다.
- 부모는 모든 하위 보고를 관찰하고 평가한 뒤에만 완료합니다.
- 의미 있는 동작마다 가장 작은 실용적인 Red → Green → Refactor를 수행합니다.
- 기능 또는 통합 결과마다 독립 검토를 받으며, 보안·권한·결제·데이터 삭제·마이그레이션·배포에는 최종 검토를 추가합니다.

하위 보고에는 결과, 변경 path, 검사, 위험 또는 차단 요인이 포함됩니다. 부모는 이를 통합하고 결과, 검토 결과 또는 수정, 남은 위험을 보고합니다.

## Routing

새 세션과 하위 에이전트에는 `gpt-6-luna`, `gpt-6.1-terra`, `gpt-6.1-sol`, `gpt-6-astra`만 사용합니다. 1차 분류·기계적인 편집은 Luna 낮음, 구현 방법이 명확한 구현·테스트 수정은 Luna 중간을 사용합니다. 국소적인 코드·테스트 원인 분석과 모호한 시각적 UI 진단은 GPT 6.1 Terra 높음, 기준이 명확한 브라우저 검증·시각적 UI 확인은 중간, 제공된 근거를 바탕으로 한 단순한 기능 문서 재작성은 낮음을 사용합니다. 일반 기능 구현·테스트·계획·일상적인 조율은 GPT 6.1 Sol 중간, 아키텍처·어려운 진단·복잡한 시스템 간 작업·고위험 최종 검토를 포함한 독립 검토는 GPT 6.1 Sol 높음을 사용합니다.

위 배정을 작업별 기본값으로 사용하되 실제 요구사항이나 결과에 근거가 있을 때 조정합니다. 매우 높음은 사용자가 명시적으로 요청하거나 유사 작업에서 품질 향상이 확인된 경우에만 사용합니다.

사용자가 명시적으로 요청한 경우를 제외하면, Sol 높음의 집중 진단과 독립적인 Sol 검토 후에도 진행을 막는 구체적이고 중요한 추론 문제가 남을 때만 Astra 높음을 사용합니다. 복잡성·위험도·정보나 도구 부족만으로는 상향하지 않습니다. Astra에는 미해결 질문만 맡기고 이후 실행은 Sol로 돌려보냅니다. Astra 매우 높음은 사용자가 명시적으로 요청한 경우에만 사용합니다. [전체 라우팅 정책](docs/SKILL.ko.md#routing)을 참고하세요.

## 사용 방법

원하는 결과를 설명하세요. 예를 들면 다음과 같습니다.

```text
청구 보고서에 CSV 내보내기를 추가해줘. 권한 검증, 회귀 테스트,
오류 상태 검토도 포함해줘.
```

작업 흐름을 직접 요청할 수도 있습니다.

```text
GPT Balance Orchestrator를 사용해서 알림 파이프라인을 안전하게 리팩터링해줘.
```
