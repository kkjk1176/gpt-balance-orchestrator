# GPT Balance Orchestrator

[Read in English](README.md)

`GPT Balance Orchestrator`는 중요도가 있는 코드 변경 기능·리팩터링·테스트 추가를 위한 Codex 스킬입니다. 작업별 요구사항과 품질 기준에 적합한 모델 역량·추론 수준을 배정하고, 불필요하게 과도한 모델 사용을 피하여 토큰 효율을 높입니다.

병렬 실행이나 맥락 분리에 구체적인 실익이 있을 때만 실행을 위임하며, 그 외 하나의 연속된 작업은 주 세션이 직접 수행합니다. 어느 경우든 독립 검토는 필수입니다.

## 유지하는 정책

- 병렬 작업의 쓰기 path와 동작 계약은 겹치지 않습니다.
- 부모는 모든 하위 보고를 관찰하고 평가한 뒤에만 완료합니다.
- 의미 있는 동작마다 가장 작은 실용적인 Red → Green → Refactor를 수행합니다.
- 기능 또는 통합 결과마다 독립 검토를 받으며, 보안·권한·결제·데이터 삭제·마이그레이션·배포에는 최종 검토를 추가합니다.

하위 보고에는 결과, 변경 path, 검사, 위험 또는 차단 요인이 포함됩니다. 부모는 이를 통합하고 결과, 검토 결과 또는 수정, 남은 위험을 보고합니다.

## Routing

우선 사용하는 모델은 `gpt-6-luna`, `gpt-6.1-terra`, `gpt-6.2-sol`, `gpt-6.2-astra`입니다. GPT-6.2 Sol과 Astra는 [2026년 11월 17일 출시](https://learn.chatgpt.com/docs/whats-new/gpt-62-astra-sol)되었으며, 11월 18일에 배정 기준을 확인했습니다.

| 작업 | 기본 배정 |
| --- | --- |
| 1차 분류·기계적인 편집 | Luna 낮음 |
| 구현 방법이 명확한 구현·테스트 수정 | Luna 중간 |
| 시각적 UI 진단 | GPT-6.1 Terra 높음 |
| 기준이 명확한 브라우저·시각 검증 | GPT-6.1 Terra 중간 |
| 단순한 기능 문서 재작성 | GPT-6.1 Terra 낮음 |
| 일반 기능·테스트·계획·조율 | GPT-6.2 Sol 중간 |
| 코드 원인 분석·아키텍처·시스템 간 작업·독립 및 최종 검토 | GPT-6.2 Sol 높음 |
| Sol 진단과 독립 검토 후에도 남는 중요한 추론 문제 | GPT-6.2 Astra 높음 |

위 배정을 작업별 기본값으로 사용하되 실제 요구사항이나 결과에 근거가 있을 때 조정합니다. XHigh 또는 Max는 사용자가 명시적으로 요청하거나 유사 작업에서 품질 향상이 확인된 경우에만 사용합니다. Ultra는 명시적인 사용자 요청, 런타임 지원, 자동 위임에 대한 허용이 필요합니다. Astra는 높음보다 높은 추론 수준을 사용자가 명시적으로 요청한 경우에만 사용합니다.

기존 비용 절약 정책에 따라, 사용자가 명시적으로 요청한 경우를 제외하면 Sol 높음의 집중 진단과 독립적인 Sol 검토 후에도 진행을 막는 구체적이고 중요한 추론 문제가 남을 때만 Astra 높음을 사용합니다. 복잡성·위험도·정보나 도구 부족만으로는 상향하지 않습니다. Astra에는 미해결 질문만 맡기고 이후 실행은 Sol로 돌려보냅니다.

실제 작업 배정 도구가 지원하는 모델·추론 수준을 먼저 확인합니다. Luna가 없으면 분류·기계적인 편집은 Terra로, 구현·테스트는 Sol로 대체합니다. Terra가 없으면 필요한 도구를 갖춘 Sol로 대체합니다. `gpt-6.1-sol`과 `gpt-6-astra`는 대응하는 GPT-6.2 모델을 사용할 수 없을 때의 대체 모델입니다. 대체 사실을 보고하고 Astra 사용 조건은 유지합니다. 스킬은 배정 기준을 안내하며 실행 중인 주 세션의 모델을 바꾸지는 않습니다. [전체 라우팅 정책](docs/SKILL.ko.md#routing)과 [모델 근거](.codex/skills/gpt-balance-orchestrator/references/models.md)를 참고하세요.

## 사용 방법

원하는 결과를 설명하세요. 예를 들면 다음과 같습니다.

```text
청구 보고서에 CSV 내보내기를 추가해줘. 권한 검증, 회귀 테스트,
오류 상태 검토도 포함해줘.
```

작업 흐름을 직접 요청할 수도 있습니다.

```text
GPT Balance Orchestrator를 사용해서 알림 파이프라인을 안전하게 리팩터링해줘.
```
