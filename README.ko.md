# GPT Balance Orchestrator

[Read in English](README.md)

`GPT Balance Orchestrator`는 의미 있는 소프트웨어 변경을 하나의 잘 관리된 기능 작업 흐름으로 만들어 주는 Codex 스킬입니다. 아주 작은 수정까지 거창한 프로젝트처럼 다루지 않으면서도, 기능을 일관된 단위로 계획하고 구현하고 검토하고 검증하도록 돕습니다.

## 어떤 때 사용하나요?

명확한 완료 기준, 집중된 테스트, 신중한 위임, 독립적인 검토가 필요한 기능 추가·리팩터링·테스트 보강에 적합합니다. 산발적인 수정의 묶음이 아니라, 믿을 수 있는 결과로 이어지는 작업 흐름이 필요할 때 사용하세요.

단순한 문서 수정이나 명백히 안전한 한 줄 변경에는 이 스킬이 의도적으로 가볍게 동작합니다. 언제 절차를 줄여야 하는지 판단하는 것도 좋은 엔지니어링의 일부이기 때문입니다.

## 어떻게 동작하나요?

이 작업 흐름은 시작부터 끝까지 책임과 검증 상태를 분명하게 유지합니다.

1. **기능의 범위를 잡습니다.** 에이전트는 완료 기준, 영향 범위, 테스트 명령, 위험 요소, 그리고 독립적으로 처리할 수 있는 가장 작은 응집된 작업 단위를 정리합니다. 위임이 필요한 경우 각 에이전트의 범위를 명확히 하고, 최종 결과의 책임은 부모 에이전트가 계속 가집니다.
2. **피드백 루프로 구현합니다.** 각 작업 단위는 Red → Green → Refactor 순서를 따릅니다. 먼저 의도한 동작을 집중된 테스트로 표현하고, 필요한 최소한의 변경을 구현한 뒤, 테스트가 통과하는 상태에서 설계를 다듬습니다. 이런 방식으로 테스트할 수 없는 작업은 가능한 가장 가까운 실행형 검증을 사용합니다.
3. **독립적으로 검토합니다.** 별도의 검토자가 요구사항 누락, 회귀, 경계 사례, 테스트 품질을 확인합니다. 명확하고 범위가 작은 지적은 수정 후 다시 확인하며, 불확실하거나 위험도가 높은 이슈는 추측으로 처리하지 않고 상위 검토 경로로 올립니다.
4. **통합하고 마무리합니다.** 완료된 단위를 의존성 순서에 따라 통합하고, 관련된 집중 테스트와 통합 검증을 실행합니다. 남은 위험이나 확인하지 못한 항목은 숨기지 않고 명확히 보고합니다.

덕분에 조율, 구현, 검토, 검증의 모든 단계에 책임자가 분명히 존재합니다.

## 내장된 작업 경로

이 스킬은 작업 성격에 맞춰 적절한 수준의 노력을 배정합니다. 작고 분명한 변경에는 가벼운 실행 경로를 사용하고, 영향 범위가 넓은 작업에는 더 강한 계획·비평·진단·최종 검토 경로를 선택합니다. 보안, 권한, 결제, 데이터 삭제·마이그레이션, 배포 변경은 높은 수준의 최종 검토를 거칩니다.

또한 흔한 위임 문제를 피합니다. 하위 에이전트는 실행한 검증, 변경한 경로, 막힌 지점을 포함한 결과를 부모에게 보고하고, 부모는 그 결과를 평가하기 전에는 기능을 완료로 처리하지 않습니다.

## 사용 방법

원하는 결과를 자연스러운 언어로 설명하면 됩니다. 예를 들면 다음과 같습니다.

```text
청구 보고서에 CSV 내보내기를 추가해줘. 권한 검증, 회귀 테스트,
오류 상태 검토도 포함해줘.
```

변경 규모가 크다면 작업 흐름을 직접 요청할 수도 있습니다.

```text
GPT Balance Orchestrator를 사용해서 알림 파이프라인을 안전하게 리팩터링해줘.
```

스킬은 이 요청을 응집된 기능 단위로 나누고, 알맞은 구현·검토 경로를 선택하며, 완료 시 실행한 검증과 남은 위험을 보고합니다.

## 기대할 수 있는 결과

- 구현 전에 “완료”의 의미를 분명히 정의합니다.
- 의미 있는 변경마다 테스트 또는 가장 가까운 실행형 검증을 수행합니다.
- 구현자의 자체 확인에만 의존하지 않고 독립적인 검토를 거칩니다.
- 변경 내용, 검증 결과, 검토 사항, 남은 위험을 간결하게 정리해 드립니다.

목표는 절차를 늘리는 것이 아닙니다. 중요도가 있는 변경을 더 신뢰하기 쉽고, 검토하기 쉽고, 개선하기 쉽게 만드는 것입니다.
